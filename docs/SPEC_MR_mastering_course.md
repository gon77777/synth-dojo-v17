# 仕様書: マスタリング講座(MR)と、そのために足りない機能

対象アプリ: シンセ道場 v15(`synth-dojo-v15.zip` のコードと `docs/` を読んで作成)
目的: 「マスタリング」を学べるコース **MR** を追加する。ただし今のマスター段は、リミッターの天井が -1 dB 固定など、マスタリングの練習に足りないものが多い。そこで、**足りない機能の洗い出し → 機能の追加 → レッスン** を、段階(MR-0〜MR-6)に分けて進める。

> この仕様書は設計案。§0 の「確認した事実」はコードの該当箇所つき。§2 以降の数値(初期値・範囲・目標値)は「案」で、耳と測定で確かめて調整する前提。**確認できていないことは §9 に分けて書いた**(MR-0 で先に確かめる)。

## 1. 方針と範囲

### 1.1 マスタリングの扱い方

- このアプリでのマスタリングは **「完成したミックスの最後の仕上げ」**。目的は3つ: ①音のバランス(トーン・幅)を整える、②音圧(ラウドネス)と山(ピーク)を目的に合わせる、③配信・再生の環境で崩れないか確かめる。
- ミックスの直し(トラックの音量・EQ)は **MX・XB・XE など既存コースに戻す**。MR は「マスターで直すのは最後の少しだけ」という態度を保つ(ms02 と同じ)。
- 1本のレッスンで覚えることは **1つ**。聞き比べ(`cmp`)で違いを耳で確かめてから言葉にする。**音量を揃えて比べる**ことを、全レッスンの共通の作法にする。
- 目標の数値は **アプリの中の値(`loud.js` のプリセット)** として示す。外部の規格名・サービス名・年号は本文に書かない(既存の本文ルールに合わせる)。

### 1.2 既存コースとの役割分担

| 既存 | 視点 | MR との違い |
|---|---|---|
| MS | 仕上げの**チェック**(確認の習慣) | MR は仕上げの**道具の使い方**。MS の ms01〜ms03 は入口として残し、MR から「深めたい人はこちら」へつなぐ |
| LM | メーターの**読み方** | MR は読んだ値を**目標にして仕上げる**(`mt` 測定目標で合格判定) |
| XB | バスの設計・ヘッドルーム | MR は xb05(ヘッドルーム)を前提にし、マスターバスの「その先」を扱う |
| XC | ダイナミクスの設計 | MR は **マスターのリミッター・押し込み**に絞る(xc07 を前提) |

### 1.3 範囲外

- 曲間・アルバムの並べ方(間隔・音量の揃え)、DDP・メタデータ、実際のコーデック(MP3・AAC)でのエンコード。
- 機種・サービスごとの細かい基準値の解説(アプリ内のプリセットを使う)。
- 自動マスタリング(AI による自動調整)。

## 2. 足りないものの洗い出し

優先: **A**=これが無いとコースが成り立たない / **B**=あると教えられる幅が大きく広がる / **C**=あれば良い・判断が要る。「段階」は §6 の実装順。

### 2.1 リミッター・音圧まわり

| G-03 | **押し込み量(入力ゲイン)が無い** | 音圧は「リミッターにどれだけ入れるか」で決まる。今は入れる量を決められない(§0 #6) | `limGain`: 0〜+18 dB、既定 0。リミッターの手前に入力ゲインを置く | A | MR-1 |
