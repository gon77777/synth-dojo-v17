## A. 確認事項の答え
| # | 確認事項 | 答え(根拠) |
|---|---|---|
| 1 | `mel()` の `idx` 値は何か | **半音オフセット**。`kitTrack` が `n+idx[i]` を音高にする(app.js:1699)。スケール内の音度ではない。`mel(name,sc,arr)` は `arr[i]` をステップ `i*2` に置く(=8分刻み・最大8音) |
| 2 | `o.tr` | 基準音からの**半音の移調**。基準音は音色の `demo.n[0]`。`bass` は36なので `tr:24` で **60=C4**。和音トラックも同じ |
| 3 | `o.scale` | **発音には使われない**(保存・表示・編集時の「スケールに寄せる」だけ)。未指定は `chrom`。`kitTrack` の `key` は **`scale==='minor'` のときだけ `n%12`、他は常に0**。→ `scl(name,key)` で別の主音のスケールを表示したいなら `kitTrack` に `o.key` を足す必要がある(発音は変わらない) |
| 4 | TRK のステップ幅 | **1ステップ=16分音符**(1小節=16ステップ。拍子つきは `stepsPerBar`)。`kitTrack` の `steps` は**16要素固定・`len` は最大16**(app.js:1698,1702) |
| 5 | コースの登録形 | `SD.CATS.push({id,synth:'analog',chapter:'course',course,name})`。目次は `chapter==='course'` を全部並べ、レベル絞り込みは `l.lv===lvf`。**MU/AL を足すだけで目次に出る**(app.js:711) |
| 6 | 用語 | `SD.TERMS` は course.js:18 で作る配列。th.js 冒頭の `A(id,name,kana,en,def,see,tags)` と同じ形で push |

## B. 仕様書とのずれ・新しく分かったこと(重要度順)
1. **2小節のリックは TRK に載らない(AL-1 に影響)**。`kitTrack` が16ステップで切るため。元の47種のうち2小節は5種、1小節は42種。validate は `len` 32まで許すが `kitTrack` は16止まり。→ AL では**1小節のリックだけを使う**(20種前後なら足りる)か、`kitTrack` の上限を32に広げるかを AL-1 で決める。仕様書の「小節数に収まる」検査は「1小節=16ステップ以内」でよい。
2. **和音は3〜4音と `test/seq.js:131` が検査している**。9th 系(5音)は入れられない。→ **決定案**: 追加する和音は **4音以内**に収める。`9`=ルート・3度・7度・9度(5度省略)、`m9`・`maj9` も同様。`m7b5`(0,3,6,10)・`dim7`(0,3,6,9)・`aug`(0,4,8)・`6`(0,4,7,9)・`m6`(0,3,7,9) は4音以内でそのまま入る。制限は広げない。
3. **`kitTrack` の `key` 問題**(A-3)。TRK のスケール表示を D ドリアンにしたいとき、いまは key=0 になる。MU-1 で `o.key` を受け付ける1行を足す案(既存レッスンは `o.key` を使わないので再生・保存は変わらない)。
4. **未知のスケール名は読み込み時に `minor` に戻る**(seq.js:80,210)。旧版が新データを開く場合だけの話で、新→新は問題なし。**旧データ(5種)は何も変わらない**。未知の和音 `cd.t` は `cleanStep` が `cd` を落とすだけで音は残る。
5. **SCALE ボタンの幅**: `pickscale` は 33% 幅で折り返す一覧(`.sb` は縦スクロール可)。5種→追加後 約13種でも**溢れず縦に伸びるだけ**。ただし SEQ/TRK 画面の `#scb` ボタンは**現在のスケール名を表示するだけ**なので、名前が長いと切れる可能性(「ミクソリディアン」「メロディックマイナー」は要実機確認)。レッスン専用にして一覧から隠す案は、一覧の実害が小さいので**不要と判断**(利用者が確認してよい)。
6. **和音ボタン**: `chsel` は 25% 幅で 10種→約18種になり 5 行。`.sb` スクロールで可。ボタン内は `根音+sym` を表示するので、`sym` は短く(`m7b5`、`dim7`、`aug`、`6`、`m6`、`9`、`m9`、`M9`)。
7. **用語・年号の検査**: 本文(`h`+`b`)・コラム・用語の定義に `19xx/20xx` を書くと NG(HS 以外)。「第7音」「12小節」などは OK だが、4桁の数字は避ける。
8. **`pre` は存在するレッスンIDのみ**(validate)。MU の pre の `th03`〜`th06` は実在。AL の pre は MU・AL 内 ID なので、**mu を先に作らないと al の pre が通らない**(段階表の順序どおりなら問題なし)。AL を MU-3 までで始める場合は、まだ無い mu の pre を外して作る。
9. **ステップ数は 3〜8**(validate)。仕様は 5〜8。MU/AL 用の検査関数で 5〜8 を別に見る。
10. **quiz には cmp が必要**で `ans` は cmp の個数以内(validate)。「耳で答える」クイズは各ステップに cmp を付ける形になる。`cmp` は `{l,mt:[ミュートするトラック番号]}`(0始まり)。
11. **スクリプト一覧の持ち主が別々**: `www/index.html`、`www/sw.js` の `F`、`test/validate.js`、`test/quality.js`(`hs.js` の後ろ)。`test/pats.js` は `hs.js` までと `eq.js` を読む別一覧。`test/cmest.js` も別一覧。MU-1 で `muh.js` を足すときは `th.js` の前後関係(依存なし=複製)に注意し、`pats.js`・`cmest.js` に必要か確認する。
12. **docs/ をアプリが読まない**ことは現状 OK(`www/` から `docs/` への参照なし)。
13. **`package.json` の version は 11.0.0 のまま**(README は v11.2)。段階ごとに合わせるか利用者に確認(既存の不整合。今回は触らない)。

## C. 素材の確認(仕様 §5.2・§5.3)
- **スケール**: `chord/scales.js` の `SC('id','英名','和名',[半音],'度数',{par,ch,cd,cn,…})`。dorian `[0,2,3,5,7,9,10]`・phrygian `[0,1,3,5,7,8,10]`・lydian `[0,2,4,6,7,9,11]`・mixolydian `[0,2,4,5,7,9,10]`・locrian `[0,1,3,5,6,8,10]`・harmonic_minor `[0,2,3,5,7,8,11]`・melodic_minor `[0,2,3,5,7,9,11]`。元の ID は `harmonic_minor`・`melodic_minor`。**シンセ道場では仕様どおり `harmonic`・`melodic` を使う**(新規IDなので自由)。`aeolian`・`ionian` は既存 `minor`・`major` と同一なので**作らない**。
- **mpent**: `adlib/core/theory.js` の `mpent`=`[0,3,5,7,10]`、`Mpent`=`[0,2,4,7,9]`。**シンセ道場の既存 `penta` は `[0,2,4,7,9]`=メジャーペンタ**(seq.js:4)。→ `mpent` を新規追加し、`penta` の別名にしない(仕様どおり)。リックの `Mpent` は既存 `penta` を使う。
- **度数表記と半音の並びの一致検査**: 元アプリの検査の実コードは `index_REFERENCE_ONLY.html` 側(未読)。MU-1 で `test/` に「度数文字列→半音を計算して一致」を見る検査を書く(♭=−1・♯=+1・基準 `1 2 3 4 5 6 7`=`0 2 4 5 7 9 11`)。
- **リック**: 47種(1小節42・2小節5)。`st+len` の最大は32、`r` の範囲は −5〜17。1小節に限れば `st+len≤16`。**`r` が負(ルートより下)がある**ので、TRK の基準音(C4=60)に足して `SD.NMIN`(24)以上か検査する。スケールは mpent・blues・Mpent・nmin の4種(`mpent`・`blues`・`penta`・`minor` に対応)。
- **元アプリのテスト**(`adlib/tests/`)は Node で未実行。AL-1 で必要なものだけ移植する。
